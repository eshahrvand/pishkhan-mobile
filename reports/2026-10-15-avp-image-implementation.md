# ساخت AvpImage و انتقال تصاویر برنامه

تاریخ: ۲۰۲۶/۱۰/۱۵

## نتیجهٔ پیاده‌سازی

ویجت عمومی `AvpImage` در پکیج `avp_ui` ساخته و از مسیر عمومی `package:avp_ui/avp_ui.dart` صادر شد. تمام ۱۳۲ مورد ساخت مستقیم ویجت SVG و ۹ مورد تصویر معمولی در ۸۶ فایل Dart برنامه به این ویجت منتقل شدند.

نمونهٔ مصرف جدید:

<pre dir="ltr">AvpImage(
  image: asset,
  width: 20,
  height: 20,
)</pre>

فایل اصلی در پکیج همسایه قرار دارد:

[پیاده‌سازی AvpImage](../../avp_ui/lib/widgets/images/avp_image.dart)

## قابلیت‌های حفظ‌شده از نمونهٔ ارائه‌شده

- نمایش SVG و تصاویر معمولی از asset.
- نمایش تصاویر HTTP و HTTPS؛ تصاویر معمولی شبکه از cache manager استفاده می‌کنند.
- نمایش SVG و Lottie از شبکه، همراه با امکان ارسال header.
- نمایش فایل‌های محلی SVG، تصاویر معمولی و Lottie روی پلتفرم‌های native.
- نمایش Lottie JSON و کنترل پخش و تکرار آن با `animate` و `repeat`.
- placeholder برای ورودی خالی، بارگذاری و خطا.
- نمایش دایره‌ای با `isCircle` و ابعاد اختیاری `circleWidth/circleHeight`.
- حالت placeholder کوچک با `isMicro`، رنگ معنایی پروژه و شعاع ۱۶ پیکسلی پکیج.
- اندازه، fit، alignment، padding، رنگ پس‌زمینه و tint.

## اصلاح‌های متناسب با این پروژه

نام کلاس از `CaltivitaImage` به `AvpImage` تغییر کرد؛ هیچ import، تم، پالت یا cache manager اختصاصی پروژهٔ قبلی کپی نشد.

`placeHolder` به `placeholder` و `boxFit` به `fit` تبدیل شدند. ورودی‌های boolean غیر nullable هستند و پیش‌فرض مشخص دارند. مقدار پیش‌فرض `fit` برابر `BoxFit.contain` است تا با مصرف معمول SVG در این پروژه هماهنگ باشد.

تشخیص شبکه بر اساس scheme واقعی URI انجام می‌شود؛ وجود عبارت https در نام asset آن را به تصویر شبکه تبدیل نمی‌کند. نوع تصویر از path و مستقل از query string تشخیص داده می‌شود و بزرگی یا کوچکی حروف پسوند مهم نیست. برای URL بدون پسوند، `AvpImageType` امکان انتخاب صریح نوع را فراهم می‌کند.

ورودی null یا خالی و placeholder ناموجود باعث استفادهٔ ناامن از `!` یا بازگشت بی‌پایان نمی‌شوند. در نبود fallback معتبر، یک فضای خالی با اندازهٔ تعیین‌شده باقی می‌ماند.

`semanticsLabel` برای تصویر معنادار و `excludeFromSemantics` برای تصویر تزئینی اضافه شده‌اند. padding جهت‌پذیر است و mirroring تصاویر asset و شبکه با `matchTextDirection` قابل انتخاب است.

دسترسی فایل با conditional import جدا شده است؛ فایل‌های native وارد مسیر اجرای وب نمی‌شوند. در مرورگر، مسیر فایل محلی به fallback می‌رسد. نمایش فایل انتخاب‌شدهٔ مرورگر به قرارداد bytes/blob جداگانه نیاز دارد.

## مدیریت خطای SVG

تست خطا نشان داد Futureهای ثانویهٔ cache در کتابخانهٔ SVG و renderer می‌توانند خطای بارگذاری را با وجود `errorBuilder` نیز بیرون بدهند. به همین دلیل بارگذاری و کامپایل SVG پیش از نصب renderer انجام می‌شود. FutureBuilder خطای I/O یا کامپایل را به fallback تبدیل می‌کند و فقط دادهٔ کامپایل‌شدهٔ موفق به renderer تحویل داده می‌شود.

theme قبل از await خوانده می‌شود و تغییر منبع از چرخهٔ عمر ویجت پیروی می‌کند. از compiler موجود در ابزارهای SVG استفاده شده است؛ parser جدیدی نوشته نشده و handler سراسری خطا تغییر نکرده است.

## کش و شبکه

برای تصاویر معمولی شبکه می‌توان `cacheManager`، `cacheKey` و `headers` داد. default manager از کش دیسکی native استفاده می‌کند؛ این کش قابل پاک‌شدن توسط سیستم‌عامل است و ذخیره‌سازی دائمی دادهٔ کاربر محسوب نمی‌شود. محدودیت کش وب در [مستند رسمی cached_network_image](https://pub.dev/packages/cached_network_image) توضیح داده شده است.

مانند نمونهٔ اولیه، SVG و Lottie شبکه از loader خودشان استفاده می‌کنند و از کش دیسکی تصاویر معمولی عبور نمی‌کنند. مالکیت احراز هویت، آدرس مجاز، تفکیک کلیدهای کش، مدت نگهداری و پاک‌سازی متعلق به برنامهٔ میزبان است. جزئیات نگهداری و حذف فایل‌ها در [راهنمای flutter_cache_manager](https://pub.dev/packages/flutter_cache_manager) آمده است.

## وابستگی‌ها

با تأیید صریح صاحب پروژه برای حفظ Lottie و کش شبکه، موارد زیر در پکیج ثبت شدند:

| وابستگی | نسخهٔ ثبت‌شده | کاربرد |
| --- | --- | --- |
| cached_network_image | `^4.0.4` | نمایش و کش تصویر معمولی شبکه |
| cached_network_image_platform_interface | `^5.0.3` | انتخاب روش HttpGet برای نمایش وب |
| flutter_cache_manager | `^3.4.5` | قرارداد cache manager قابل تزریق |
| lottie | `^3.6.1` | نمایش انیمیشن JSON |
| vector_graphics_compiler | `^1.3.0` | استفادهٔ مستقیم از compiler موجود برای مدیریت امن خطای SVG |
| file | `^7.0.1`، فقط تست | فایل آزمایشی سازگار با cache manager |

نسخه‌های resolved در lockfileها ثبت شدند. وابستگی مستقیم جدیدی به pubspec برنامه اضافه نشد؛ برنامه وابستگی‌های جدید پکیج محلی را دریافت کرد. فایل‌های ثبت خودکار plugin و lockfile مثال پکیج نیز با وابستگی‌های native جدید هماهنگ شدند.

## محدودهٔ انتقال در برنامه

اندازه‌ها، fitهای موجود، assetها، callbackها و ساختار صفحات در محل مصرف حفظ شدند. importهای مستقیم `flutter_svg` از کد نمایش برنامه حذف شدند. برای آیکون منوی کارت شغل، اندازهٔ اصلی ۲۰×۲۰ صریح شد تا هنگام بارگذاری نیز ناحیهٔ کلیک وجود داشته باشد.

`AssetImage` مورد استفاده برای خواندن texture داشبورد و تولید `ui.Image` در painter باقی مانده است؛ آن کد ویجت نمایش عکس نیست. pre-cache تصاویر در تست‌ها نیز همچنان معتبر است. اجزای داخلی قدیمی خود پکیج بدون ضرورت به‌صورت سراسری بازنویسی نشدند.

## بررسی و تست

نتیجهٔ اجرای نهایی:

- کل تست‌های برنامه: **۳۳۷ تست پاس شد**.
- کل تست‌های پکیج: **۱۳۶ تست پاس شد**؛ شامل ۱۰ تست اختصاصی تصویر.
- build وب: موفق.
- تحلیل فایل‌های جدید تصویر، تست‌های تصویر و export عمومی پکیج: بدون ایراد.

فرمان‌های اصلی در هر مخزن:

<pre dir="ltr">flutter test --no-pub --reporter expanded
flutter build web --no-pub --debug
flutter analyze --no-pub lib/widgets/images test/widgets/avp_image_test.dart lib/avp_ui.dart</pre>

فرمان build در مخزن برنامه و فرمان آخر در مخزن پکیج اجرا شد. لاگ‌های تست در خروجی‌های ignored زیر `build/` نگهداری شدند. دو موردی که در اجرای اولیهٔ کامل مشخص شدند، پیش از اجرای موفق نهایی اصلاح شدند: انتظار تست پکیج برای پایان واقعی بارگذاری و اندازهٔ ناحیهٔ کلیک منوی کارت شغل.

ده تست اختصاصی، نمایش asset، نوع SVG با حروف بزرگ، ورودی خالی، منبع ناموجود، placeholder ناموجود، نمایش دایره‌ای، رنگ و اندازه، فایل و URI فایل، Lottie، cache manager تزریق‌شده و دسترس‌پذیری را پوشش می‌دهند. برای SVG و Lottie شبکه، یک سرور HTTP محلی در تست راه‌اندازی می‌شود و ارسال header و تشخیص نوع مستقل از query بررسی می‌شود.

build وب با نسخهٔ نهایی ویجت موفق شد و dry run مربوط به Wasm نیز موفق بود. این بررسی، اجرای واقعی روی دستگاه Android یا iOS و بررسی شبکهٔ production نیست.

تحلیل فایل‌های جدید پکیج و تست‌های تصویر بدون ایراد پایان یافت. تحلیل کامل برنامه خطای کامپایل گزارش نکرد، اما هشدارهای قبلی اعضای استفاده‌نشده و قالب مسیر محلی `avp_ui` باقی مانده‌اند؛ در آن اجرا ۲۴ هشدار شامل تکرار هشدار مسیر گزارش شد.
