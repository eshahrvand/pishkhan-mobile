## قرارداد نهایی DI و چرخهٔ عمر

GetIt فقط وابستگی‌های دادهٔ موجود را ثبت می‌کند. هیچ Cubit/Bloc، حتی برای
شیت یا بخش داخلی صفحه، در locator ثبت یا از آن دریافت نمی‌شود.
ساخت مستقیم در `BlocProvider.create` داخل صفحه انجام می‌شود؛ Repository در
خود Cubit از GetIt دریافت می‌شود و ورودی سازندهٔ Cubit، صفحه یا child نیست. نمونه:

```dart
BlocProvider<CardFeaturesCubit>(
  create: (_) => CardFeaturesCubit(
    initialCategory: initialCategory,
  )..load(),
  child: ...,
)
```

Home Provider از GoRouter به DashboardScreen منتقل شده است.
بدنه‌های چندشاخهٔ listener به متدهایی مانند `_handleEffect` منتقل شدند؛
UI فقط اجرای effect را انجام می‌دهد.

Provider مالک نمونه و بستن آن است؛ تب‌های داشبورد همان HomeCubit مشترک
را می‌خوانند. تست DI نبودن ثبت Cubitها، مستقل‌بودن State جریان‌ها و حفظ
State ورودی تا فراخوانی اکشن اولیه را بررسی می‌کند.

## مرزهایی که باید در UI باقی بمانند

- ساخت و dispose کنترلر، focus، video، animation و منابع decoded image؛
- اندازه‌گیری TextPainter، viewport، SafeArea، زمان‌بندی وابسته به layout و hasClients/mounted؛
- ترجمهٔ enum و قالب‌بندی دادهٔ ازپیش‌محاسبه‌شده؛
- اجرای intent مسیریابی و effect شیت/پیام و برگرداندن نتیجهٔ خام به Cubit.

وجود `_createVideo` ساخت Cubit نیست. ValueNotifier مربوط به texture مالک
`ui.Image` است و جایگزین State جریان نیست. `didChangeDependencies` پنل Reso
از وابستگی‌های واقعی locale/layout و ImageConfiguration استفاده می‌کند؛
مشابه پرچم اضافی اولیهٔ فهرست کارت نیست.

## محدودیت ظاهری موجود

فیلد آدرس لاتین گواهی تمکن، کنترل نمایشی اختصاصی ۹۰ پیکسلی دارد؛ حداقل ارتفاع
چندخطی API فعلی avp_ui برابر ۱۳۰ پیکسل است. تغییر این بخش به کامپوننت عمومی
بدون variant سازگار، ظاهر فعلی را عوض می‌کند. در این بازآراییِ مالکیت منطق،
این کنترل ظاهری حفظ می‌شود؛ این مورد انطباق کامل کنترل‌های UI با بسته را ثابت
نمی‌کند و برای رفع آن باید variant مناسب در بستهٔ مستقل فراهم شود.

## اعتبارسنجی آخرین اصلاح

نتیجهٔ اجرای نهایی این اصلاح پس از تکمیل تست‌ها ثبت می‌شود.

### اجرای قبلی

- تولید Freezed با `dart run build_runner build`: موفق.
- تحلیل `lib/core`، چهار فیچر و تست‌های مرتبط با `flutter analyze --no-pub`: بدون خطا، هشدار یا پیام تحلیل.
- `git diff --check`: موفق.
- اجرای کامل نهایی `flutter test --no-pub --concurrency=2`: هر ۳۶۴ تست موفق، بدون شکست (۱ دقیقه و ۳۴ ثانیه).
- تحلیل نهایی علاوه بر کد چهار فیچر، `test/support` و تست‌های DI را هم پوشش می‌دهد؛ بدون مسئله.
- جست‌وجوی نهایی در `lib`: بدون ثبت/دریافت Cubit از GetIt و بدون helper ساخت Cubit.


اجرای اولیهٔ این بازآرایی مبنای قابل اتکا برای نسبت‌دادن خطاها به نسخهٔ قبل نیست؛
نتیجهٔ بالا مربوط به اجرای مستقل روی نسخهٔ نهاییِ ثابت است. در تست وضعیت بازگشتی رمز، fixture قبلاً Repository آماده‌شده
را به صفحه وصل نمی‌کرد؛ اکنون آن را در DI ثبت می‌کند.
